# 감자칩 생산 라인 1~12번 · R23 (기계 생성 메모리 부담·중단 복구 개선)

`build_line.py`가 실행 진입점입니다. 같은 폴더의 Python 모듈을 함께 보관하세요.
Windows Python과 pywin32, CATIA V5가 필요합니다. 코드는 CATIA의 Sketch/Pad/Pocket 등으로
개별 CATPart와 CATProduct를 생성합니다. 이번 수정에서 CATIA를 실행하지는 않았습니다.

## 실행

코드 폴더에서 실행합니다.

```powershell
# 기본: 1~12번 리뷰, 기계 생성/재사용, 마지막 전체 조립
py build_line.py

# 이미 저장된 1~12번 기계만 불러와 전체 조립
py build_line.py --assemble-existing

# 기존 기계로 4번을 빼고 조립: 1→2→3→5→6→…→12
py build_line.py --assemble-existing --exclude-stage 4

# 4번 제외: 나머지 기계 생성/재사용 + 리뷰 + 조립
py build_line.py --exclude-stage 4

# 12번만 생성
py build_line.py --stage 12

# 전체 리뷰만 생성: CATIA 불필요
py build_line.py --report-only

# 개별 1~12번만 생성하고 전체 조립은 생략
py build_line.py --all

# 새 번호 폴더로 모두 다시 생성하고 조립, 참조 기계까지 ZIP에 포함
py build_line.py --assemble --rebuild --zip

# 일부 기계만 생성 / 6번까지만 전체 조립
py build_line.py --stages 3 4 12
py build_line.py --assemble --through 6

# 생성 결과 정리 대상만 확인
py build_line.py --clean --dry-run
```

기본 실행은 더 이상 1번 리뷰만 만들지 않습니다. 전체 모델링이 시작됩니다.
각 리뷰와 기계는 다음 단계로 넘어가기 전에 저장합니다. 중간에 중단되면 완료된 파일은 남고,
같은 코드·입력으로 다시 실행하면 저장된 모델 서명이 맞는 기계는 재사용합니다.
`--rebuild`는 기존 CAD를 덮어쓰지 않고 새 번호 폴더에 저장합니다.

`--assemble-existing`는 기계를 새로 만들지 않습니다. 출력 폴더 바로 아래 기계 폴더의
`MODEL_INFO.json`과 실제 CATProduct를 함께 확인하고, 여러 완성본이 있으면 CATProduct 수정시각이
가장 최근인 파일을 선택합니다. 필요한 번호가 없으면 CATIA 조립을 시작하기 전에 누락 목록을 표시합니다.
연결 컨베이어는 기존 파일을 재사용하거나 별도로 생성하며, 마지막 전체 조립은 새 폴더에 저장합니다.
기존 모델 리뷰는 그 모델 폴더에 저장된 계산 스냅샷을 사용합니다. 자료가 없으면 없다고 표시합니다.

`--exclude-stage 4`는 기본 실행, `--assemble`, `--assemble-existing`에서 사용할 수 있습니다.
4번 모델은 찾거나 생성하지 않으며, 3→4 및 4→5 대신 `Transfer_03_05`를 만듭니다.
번호를 다시 매기지 않습니다. 기존 4번 파일과 개별 리뷰는 삭제하지 않습니다.
결과는 `Potato_Line_01_12_No04/`에 저장하며, 폴더가 이미 있으면 새 번호 폴더를 사용합니다.
`--through`를 함께 쓰면 5 이상이어야 합니다. `--stage`, `--all`, `--report-only`, `--clean`과는 함께 쓰지 않습니다.
`--existing-map`에 4번 항목이 있으면 이 옵션을 사용할 때만 그 항목을 무시합니다.
전체 리뷰 목록은 보관 중인 1~12번 개별 리뷰를 유지하고, 실제 조립 순서와 제외 번호는
`Overall_Review/01_12_Assembly_Layout.html` 및 해당 조립 폴더의 `MODEL_INFO.json`에 기록합니다.

## 기계 생성 중 RPC 오류·메모리 누적 개선

`-2147023170` / `0x800706BE`는 CATIA에 대한 RPC 호출이 실패했다는 뜻입니다.
이 코드만으로 메모리 부족을 확정할 수는 없습니다. 기존 기계 생성 코드는 Part/그룹 창을 닫아도,
처음부터 열어 둔 상위 Product에 완성 그룹을 붙여 앞선 조립 데이터를 계속 유지했습니다.

R23의 `engineering_assembly.py`는 1~4번·6~11번을 다음 순서로 생성합니다.

1. 각 고유 CATPart를 생성 또는 복사하여 저장하고 즉시 닫습니다.
2. 저장된 파일 경로로 기능별 CATProduct를 만들고 각각 저장·닫습니다.
3. 마지막에 최종 기계 CATProduct를 만들고 그룹 파일을 삽입합니다.

공통 부품은 그룹 안에서 참조를 재사용하므로 반복 인스턴스마다 CATPart 창을 다시 열지 않습니다.
8번은 기존 형상 그대로 192개 고유 부품 / 673개 배치 / 10개 기능 그룹입니다.
창을 닫는 것만으로 CATIA의 모든 내부 캐시가 해제됨을 보장하는 방식은 아니며,
최종 조립을 열 때는 여전히 전체 모델을 표시할 메모리가 필요합니다. CATIA 실측 검증은 하지 않았습니다.

중단 후에는 필요한 사용자 작업을 저장하고 CATIA를 재시작한 다음 실행합니다.

```powershell
# 중단된 8번 재개 / 이미 완성된 8번이 있으면 재사용
py build_line.py --stage 8
# 나머지 생성까지 이어서 4번 제외 전체 조립
py build_line.py --exclude-stage 4
```

복구할 때 `--rebuild`는 붙이지 않습니다. 이 옵션은 기존 완성 모델과 부분 저장 부품의 재사용을
모두 건너뛰고 새로 생성하는 의미를 유지합니다. 기존 사용자 설정을 썼다면 같은 설정 옵션을 붙이세요.
완성 모델이 없으면 부분 저장 CATPart를 새 폴더에 복사한 뒤 고유 PartNumber로 저장합니다.
원본 파일은 보존하고, 누락된 부품만 새로 만듭니다. 그룹 Product는 복구한 부품으로 다시 조립합니다.

새 부분 저장 파일은 `MODEL_INFO.json`의 형상 서명·파일 해시가 일치할 때만 재사용합니다.
R22 이전 부분 저장은 개별 계산 JSON의 `geometry_sha256`이 현재 전체 형상과 정확히 일치할 때만
파일명 배치를 재현하여 복구합니다. 서명 자료가 없는 구버전은 추측해서 재사용하지 않습니다.
CATIA 파일이 실제로 손상되어 열리지 않으면 해당 파일에서 중단하고 오류를 표시합니다.
`MODEL_INFO.json`은 매 부품 저장 후 갱신되며, 실패 단계·저장 개수·RPC 여부가 기록됩니다.
이때 `build_status: failed`인 기계를 완료 모델로 취급하지 않습니다.

`--all` 및 여러 번호를 지정한 `--stages`에서도 이번 실행이 연 이전 기계 창을 닫고 다음 기계로
넘어갑니다. 마지막 기계와 사용자가 실행 전에 열어 둔 문서는 자동으로 닫지 않습니다.
통신이 끊긴 뒤 화면·경고 설정 복원까지 실패해도 최초 오류를 덮어쓰지 않도록 했습니다.

## 전체 조립 중 AddExternalComponent 오류 후 재실행

기존 코드에는 전체 조립까지 열린 문서의 COM 참조를 보관하는 방식과,
모든 연결 컨베이어의 서로 다른 부품을 `Tr_...`라는 공통 번호로 저장하는 문제가 있었습니다.
R21 이후 전체 조립에 저장된 CATProduct 경로를 `AddComponentsFromFiles`로 하나씩 삽입합니다.
조립 대상 문서를 매번 활성화하고, 기계 또는 연결부 한 개를 삽입할 때마다 저장합니다.

```powershell
py build_line.py --assemble-existing
```

이 명령은 1~12번 기계를 다시 모델링하지 않습니다. 구버전 연결부가 있으면 저장된 CATPart를
새 번호 폴더로 복사하고, 연결부별·실행별로 고유한 PartNumber를 부여해 저장합니다.
기존 형상의 생성 코드를 다시 실행하는 것이 아니라 복사본의 식별자와 조립 구조를 바꾸는 작업입니다.
연결부의 기능별 하위 Product도 각각 저장하고 닫은 뒤 부모 Product를 만들므로
저장되지 않은 하위 조립 문서에 의존하지 않습니다. 복구 완료된 연결부는 다음 실행에서 그대로 재사용합니다.
저장된 부품이 실제로 없거나 입력 형상이 달라졌다면 해당 부품은 새로 생성합니다.

기존 기계·연결부 원본과 실패한 전체 조립은 보존합니다. 이전 실행 창이 남아 있다면 필요한
사용자 편집을 저장한 뒤 CATIA를 재시작하고 위 명령을 실행하는 편이 좋습니다.
코드는 사용자가 이미 열어 둔 문서를 자동으로 닫지 않습니다.

전체 조립 콘솔은 `ASSEMBLY 1/23: 이름 <- 경로`, `SAVED ASSEMBLY 1/23`처럼 표시합니다.
개수는 선택한 공정 범위에 따라 바뀝니다. 오류가 나면 새 전체 조립 폴더의 `MODEL_INFO.json`에
`build_status: failed`, 마지막 저장 개수, 실패한 항목과 원본 파일 경로가 남습니다.
실패한 조립을 완료된 결과로 등록하지 않습니다. `--assemble-existing` 재실행은 완성된 기계와
복구된 연결부를 재사용하여 새 전체 조립 파일을 만듭니다.

다른 위치의 모델이나 특정 버전을 지정하려면 `--existing-map 경로.json`을 함께 사용합니다.
JSON은 `{"1": "C:/.../01_....CATProduct", "12": "C:/.../12_....CATProduct"}` 형식이며,
나머지 번호는 자동 검색합니다. 상대 경로는 이 JSON 파일 위치를 기준으로 합니다.
CATProduct 옆에 MODEL_INFO가 없으면 다음처럼 실제 모델 좌표계의 투입·배출점도 지정해야 합니다.

```json
{
  "12": {
    "product": "C:/Models/12_Packaging_10Line.CATProduct",
    "inlet": [-11200, 0, 478],
    "inlet_width_mm": 800
  }
}
```

`--output-dir 경로`로 지정한 폴더 아래에도 같은 구조를 사용합니다.

설정 옵션을 생략하면 코드 기본값을 사용합니다. 저장 설정이 있으면 `--vbk-config`, `--so-config`,
`--crp-config`, `--ms-config`, `--finish-config`, `--packaging-config`로 명시합니다.
전체 조립을 복사할 때는 참조하는 기계 폴더도 함께 복사하세요. `--zip`은 이 폴더들을 포함합니다.

## 12번 통합 범위

사용자가 전달한 `13_packaging_machine_10line.py`를 `packaging_machine.py`로 넣고
12번으로 등록했습니다. 공통 승강 벨트, 분배기, 독립 계량 10채널, 원형 작업대, VFFS 10대의
형상은 유지했습니다. 큰 기능별 영문 그룹으로 묶고 동일 CATPart를 반복 참조합니다.
모델 내부 번호는 재생성 시 중복 충돌을 줄이도록 실행별 접두사를 사용합니다.

12번은 CATPart 하나를 생성·저장한 직후 그 문서를 닫습니다. 기본 형상의 134개 부품을
모두 만든 뒤에는 90개 기능별 하위 Product를 자식부터 하나씩 생성·저장·닫고,
마지막에 저장된 하위 Product들을 참조하는 전체 Product를 만듭니다.
부품 창 134개와 하위 Product 창들을 동시에 열어두던 방식을 제거했습니다.
부품 색상은 CATPart에 저장한 값을 사용하며, 동일한 색상을 4,709개 인스턴스에 다시 설정하지 않습니다.
최종 조립의 부품 수와 형상은 그대로이므로 완성품을 여는 데 필요한 메모리까지 없어지는 것은 아닙니다.

이전 실행의 창이 많이 남아 있다면 필요한 사용자 수정 내용을 저장한 뒤 CATIA를 재시작하고 실행하세요.
코드가 사용자가 열어 둔 다른 문서를 자동으로 닫지는 않습니다.

```powershell
py build_line.py --stage 12 --rebuild
```

콘솔의 `SAVED + CLOSED MASTER`, `SAVED + CLOSED PRODUCT`는 해당 파일을 저장하고
창을 닫은 뒤 출력합니다. 중간 실패 시 이미 저장된 부품·하위 조립은 새 출력 폴더에 남습니다.

12번 원본의 프로파일·브라켓 구조는 아직 용접 사각관으로 재설계하지 않았습니다.
구매 모터·히터 사양, 기계 자중, 작업대 강도와 토크가 미확정이므로 리뷰에도 미확정으로 표시합니다.
원본 목표는 85g × 30봉/min × 10대 = 1,530kg/h이며, 유효계수 0.75 시나리오는 1,147.5kg/h입니다.
전체 리뷰에서는 11번 양념 혼합 후 공급량과 비교합니다. 이를 실측 생산능력으로 표시하지 않습니다.

## 조립 범위와 5번 변경

전체 조립은 모든 기계를 바닥 기준으로 배치하고 실제 투입·배출점에 따라 연결 길이를 정하는
개념 배치입니다. 11→12번은 12번에 포함된 긴 승강 컨베이어의 낮은 투입 끝에 연결합니다.
5번은 Z500에서 아래로 배출하므로 5→6번에 수평 벨트를 본체 속으로 통과시키지 않습니다.
R22는 `Transfer_05_06`에 사각 받이 슈트, 저상 수평 벨트, 경사 벨트, 연속 측면 가이드,
이송 리브, 물받이, 용접 사각관 지지대와 구동부 받침을 생성합니다. 5번의 높이는 그대로 유지합니다.
수평 벨트는 폭 440mm, 축간 1,300mm, 상면 Z150mm이며 5번 기준 −Y 방향으로 빠져나옵니다.
